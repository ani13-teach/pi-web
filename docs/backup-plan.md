# Pi Desktop 用户数据备份与恢复：首版现状与后续规划

> **首版已实现**，入口是设置中的「备份与恢复」。当前可用范围以文末「当前实施状态」和 [项目指南](project-guide.md#备份与恢复的实际范围) 为准。下文的设计、阶段清单和待决项保留为规划，不是全部已经实现的承诺；旧调查中的源码行号也可能已移动。
> 备份对象是应用使用的**会话、配置和部分自定义资源**，不是 Git 源码或整个电脑。本次文档核查未读取用户凭据内容。

## 架构与规划目标（不等于首版全部能力）

Pi Desktop 是 Electron 主进程 + 后台进程 + 渲染层架构。`services/http-router.ts` 通过 IPC 执行 `app/api` 路由，没有对外 HTTP 监听；`services/routes.gen.ts` 由 `scripts/gen-routes.mjs` 生成。设置入口在 `components/SettingsPanel.tsx`，界面在 `components/BackupSettings.tsx`，专用 IPC 在 `desktop/main.ts`，档案实现为 `lib/backup/index.ts`。现有 `app/api/sessions/[id]/export/route.ts` 只导出便于浏览的单会话 HTML，**不能用于恢复原始会话**；恢复应使用加密 `.pibak` 档案。

目标：允许用户在本机手动预览、导出和恢复选定范围的数据；迁移电脑时能恢复会话与配置；出错时不覆盖原数据。**每次导出都必须设置本次备份密码并加密整个档案**；“备份隐私信息：是/否”只决定纳入哪些数据，不决定是否加密。首版不做云同步、定时/增量备份、整个项目源码备份、依赖离线安装或正在运行的终端/任务恢复。

以下以 `A = getAgentDir()`（默认 `~/.pi/agent`，可由 `PI_CODING_AGENT_DIR` 改写）和 `P = 用户明确选择的项目目录` 表示路径。**以实际运行时解析值为准，不能写死当前机器的路径。**

## 规划中的备份对象清单（逐项实现状态见文末）

采用显式白名单、可见的范围选择；不把 `A` 或 `P` 整棵目录直接打包。优先级表示实施顺序，不表示自动包含。下表是**选择“备份隐私信息：是”时允许继续勾选的候选项**；选择“否”时只允许经过字段级检查的非隐私设置，不能从下表推断聊天记录或自由文本也能导出。

SDK CLI 支持 `PI_CODING_AGENT_SESSION_DIR`、`--session-dir` 和设置中的会话目录，但当前桌面 `lib/rpc-manager.ts:1984` 创建会话时传入 `undefined`，桌面列表按 `A/sessions` 扫描。首版额外会话目录须由用户明确选择并说明：备份到了不代表当前桌面能发现它；恢复默认落到桌面可识别目录，迁移前验证自定义目录及 CLI 的实际语义。

**两种模式都不备份**：`A/pi-web-session-index.json`（派生索引）、`trust.json`（不能继承旧环境的项目信任）、日志、锁、缓存、临时文件、未知第三方数据、大型安装包，以及仓库的 `dist/`、`release/`、`node_modules/`、`vendor/`、`.tmp-*`。`PI_WEB_PASSWORD` 等环境变量及外部密钥管理器中的秘密不在导出范围。`sessionStorage` 中的终端标签、`lib/draft-store.ts` 的内存草稿、PTY 进程、未落盘对话无法靠文件备份恢复。运行时全局目录实际混有第三方文件，故尤其不能“一键拷贝整个目录”。

## 规划中的交互与接口设计

1. 在设置中增加“备份与恢复”：选择全局/项目/会话范围，展示路径、文件数量、总大小、缺项、敏感级别和排除项；项目选择不隐含项目源码。父子会话缺失时提示补选。
2. 导出 UI 明确提供“**备份隐私信息：是 / 否**”（默认“否”），以及**每次都必填的备份密码和确认密码**；密码不符合要求或两次不一致时禁止导出。无论选择是还是否，输出文件一律整包加密，不提供明文 ZIP 选项。
3. 选“**是**”：用户仍需选择具体范围；勾选供应商时将其 URL、API key、ID、自定义请求头、OAuth 凭据及其他设置作为**同一组**导出，不能只保存 URL 却漏掉已有 key；会话原文等其他数据仍按范围选择。导出前列出敏感数据类别、缺失凭据和排除项，默认不展示密钥值。
4. 选“**否**”：必须保证不把隐私信息放进档案，而不是仅跳过 `auth.json`。采用**仅允许经过审计的非隐私字段**的严格白名单；供应商 URL/key/自定义 ID、请求头、OAuth/推送凭据、会话原文、用户指令、skills/extensions 任意文本、路径与浏览器工作区状态均不导出。无法可靠确认无隐私的条目直接禁选/跳过，预览逐项说明；如用户希望备份聊天或自定义供应商配置，提示切换到“是”。不宣称能自动从聊天或任意第三方文件中删净所有隐私。
5. 导入先验证、展示来源版本、是否包含隐私数据和目标映射、冲突与将被跳过的资源，再让用户确认“跳过 / 覆盖”；默认跳过，禁止未经确认自动覆盖。配置首版不做任意深度合并。同 ID 同内容会话可跳过，不同内容提示冲突。
6. 文件选择优先由 `desktop/main.ts` 的系统对话框完成，主进程发有时效、绑定窗口的文件授权令牌；后台只处理授权目标、执行扫描与流式归档。通过 `shared/contract.ts`、`desktop/preload.ts`、`desktop/backend.ts` 定义 `scan / export / inspect / restore / status / cancel`，不让渲染层传任意绝对路径即可读写。渲染层只接收预览元数据、进度与错误码；秘密原文、解密后的字节不可出现在前端 JSON 或日志中。浏览器 localStorage 的允许键由渲染层提供给后端或单独恢复，不复制磁盘 profile。
7. 现有 `app/api`/IPC 的请求权限与来源校验需要一并审视；如果改走 App Router，新增路由由 `scripts/gen-routes.mjs` 生成，不能手改 `services/routes.gen.ts`。首次实施推荐桌面专用 IPC，避免把导入导出能力暴露给页面通用 API。

## 规划中的格式、安全与一致性目标

- 档案定义版本化清单：格式版本、应用/SDK 版本、时间、是否包含隐私、逻辑根与来源类型、条目相对路径/大小/SHA-256、会话关联、跳过原因、完整性状态；载荷按 `global/`、`projects/<id>/`、`sessions/<rootId>/`、`ui/` 分类。清单与载荷**一起加密**，不把供应商 ID、路径等写到外部明文头部。未知主版本拒绝恢复；哈希检测损坏，但不证明来源可信。
- **只有一种导出格式：整包密码加密档案**。内部可以采用 ZIP，但外层始终使用版本化加密容器（例如 scrypt + AES-256-GCM），限定 KDF 参数与资源耗用；认证成功前不解析内部内容。每次导出必须输入并确认本次密码，恢复必须输入对应密码；没有无密码或明文导出分支。口令不写磁盘、日志或持久状态；不把未加密的秘密暂存到公共临时目录。加密无法防范已被控制的宿主进程。
- 导出不跟随 symlink/junction；导入只接受清单中的常规文件，拒绝绝对路径、`..`、UNC、盘符、ADS、大小写碰撞、重复条目及链接，限制文件数、单文件大小、总解压大小及压缩比；目标父目录在提交前再检查 reparse point，防止路径竞态。路径迁移只重写已识别的结构化字段，不做聊天正文全局替换。
- 活跃会话会写 JSONL，配置和凭据还会由 CLI/插件等外部进程改写。首版要求应用会话进入静止状态：阻止新写入，等待现有写入结束；外部写入无法锁住时提示关闭 CLI，复制前后检测变化并重试/失败，**绝不把变化中的复制冒充一致快照**。
- 导出先写同盘临时文件，完成校验与关闭句柄后重命名；取消/失败不发布半成品。恢复在受限暂存目录中解密、校验及预览，提交前复核目标文件状态。覆盖目标先建立受保护的回滚副本；跨目录提交不是原子事务，应记录持久化步骤，失败逆序恢复，崩溃重启先处理未完成事务。索引在成功后重建。
- 项目 `.pi/extensions`、`.agents/skills` 等可能执行代码；恢复不导入 `trust.json`，且**已有受信任项目的信任记录也可能自动生效**：恢复前需阻断目标项目加载，对覆盖代码资源撤销/重新确认信任或要求新建隔离目录。全局扩展也先隔离，不在恢复进程启动期间自动执行。

## 规划阶段及完整目标验收

1. **调查与契约**：确定 SDK 自定义会话目录、Electron profile/localStorage 键、各类资源根、供应商配置与 `auth.json` 中的凭据关联、非隐私字段白名单；用合成配置定义格式版本、清单 schema、隐私选项与恢复预览。新增 `lib/backup/catalog.ts`、`types.ts`、`manifest.ts` 及单测。
2. **加密基础导出**：先实现“否”模式白名单设置的预览、必填密码、整包加密、校验、取消和同盘原子发布；为“是”模式准备原始会话及供应商配置的打包逻辑，但须等第 4 阶段的关联凭据与 UI 完成并通过测试后才向用户开放。新增 `lib/backup/archive.ts`、`crypto.ts`；用运行中的会话与外部 CLI 同时写入验证竞态检测。
3. **安全恢复**：新增 `lib/backup/restore.ts`、`transaction.ts`，实现目标映射、恶意档案拦截、冲突预览、回滚及重启恢复；打通会话生命周期和信任保护。未通过故障注入前不启用覆盖操作。
4. **凭据和界面**：在加密基础上接入 `auth.json` 关联供应商凭据和可选推送信息；扩展主/后台/预加载 IPC 和 `components/BackupSettings.tsx`、`SettingsPanel.tsx`、`lib/settings-navigation.ts`，实现“是/否”、每次密码输入及预览，补充多语言文案。可移动 UI 偏好放在独立允许键列表，不复制完整 profile。

验收用**合成目录**而非真实凭据：全局/项目/选定会话导出恢复，父子分支、路径迁移、同 ID 冲突、错密码/篡改、ZIP Slip/链接/解压炸弹、磁盘不足、进程崩溃及逐步故障注入；逐项检查“是”包含所选供应商 URL、key、ID 与关联凭据，“否”不会导出任何模拟隐私字段及自由文本，两种模式都要求当次密码、输出文件都不可明文读取；确认凭据不出现在未加密文件/前端结果/日志，不继承信任，不在预览时执行扩展。运行 `npm run typecheck`、`npm run build`、`npm test` 和桌面隔离用户目录的导出—恢复—继续会话冒烟测试。交付每阶段时明确未覆盖的资源与测试结果。

**实施前待决**：是否首版支持自定义会话目录的恢复后继续使用；“否”模式可安全纳入的非隐私字段最终清单（未审计完不开放该字段）；安装版 Chromium profile 的实际位置/隔离方式；允许的档案大小与压缩库；外部资源路径/符号链接授权策略；Windows 文件占用和杀进程后的恢复顺序。这些问题不能用读取个人真实 `auth.json` 来验证。

## 当前实施状态（首版，与上文目标区分）

已经接入桌面设置入口、当次密码和隐私开关；导出始终使用 scrypt + AES-256-GCM 加密。选择“是”时保存当前全局 `models.json`（包括供应商 URL、ID、配置内的 key）和全部已保存的 `auth.json` 凭据；会话、全局自定义资源、项目资源另行勾选。选择“否”时仅导出全局 `settings.json` 中三个经过固定取值检查的字段，其余内容均不导出。导出前先扫描并预览数量、大小、类别、遗漏警告，再设置密码；不支持硬链接的目标盘使用独占新建并校验密文的回退方式，掉电仍可能留下不可用的半成品文件（不会覆盖已有备份）；导入支持密码校验、预览、默认跳过已有文件；会话可恢复到未占用的位置；供应商模型配置和凭据先隔离审阅，不能自动生效。导入的扩展不会自动运行，项目资源、扩展、技能、用户指令以及**含隐私的全局 settings.json、models.json 和 auth.json** 按每份档案独立隔离到 `A/backup-imports/<批次>`，需人工审阅迁移（模型设置及凭据可能含命令型 key/请求头，不能自动激活）；恢复中断留下的解密暂存目录在下次启动后台之前清理。

**首版使用要求与限制**：

- 扫描、导出和恢复前停止活动会话、关闭终端，并停止可能同时写数据的外部 CLI；操作期间桌面后台暂时停止，结束后重启。预览档案不需要停止后台。
- 界面/IPC 接受8至1024字符密码；扫描和导入预览的授权令牌有效10分钟，过期需重新扫描或选档案。密码丢失无法恢复。
- 当前上限为单文件8 GiB、总载荷16 GiB、10000个条目；这是代码保护上限，不是已验证任意大档案稳定的保证。选择未占用的导出文件名，并将文件保存到 agent 和所选项目目录之外。
- 选择「不备份隐私信息」只导出 `settings.json` 中经过固定取值检查的 `defaultThinkingLevel`、`theme`、`enabledModelsSync`。选择「备份隐私信息」包含全局设置、模型配置及全部已有 `auth.json` 凭据，不支持逐供应商选择；会话、自定义资源、项目资源另选。
- 当前自定义目录白名单只有 `extensions`、`skills`、`agents`、`prompts`、`themes` 和三类指令文件。**不会备份** `desktop-agents/`（内置 Agent 修改及删除记录）、`agent-memory/`、项目 `.pi/agent-memory*`、项目 `.pi/automode.local.json`、技能锁文件、项目根 `CLAUDE.md` 和祖先指令文件；不要从上面的规划表推断这些已被覆盖。
- 档案是 `PIDESK01` 版本1的分帧加密容器，不是 ZIP；内部条目及元数据一起加密。完整实现不包含规划所列的每项元数据、进度/取消接口或覆盖事务。
- 恢复界面固定不覆盖：已有目标跳过；非隐私白名单设置仅在目标 `settings.json` 不存在时写入；含隐私的设置和可执行资源一律隔离审阅。恢复后的会话仍记录原 cwd；迁移电脑不会自动修复项目路径及外部文件引用。
