# Pi Desktop 手动完整备份与恢复

> 当前实现说明。入口：「设置 → 完整备份」。架构依据见 [备份重构方案](backup-refactor-plan.md)。旧的公共/隐私模式、分类开关和 `backup-imports` 隔离恢复流程已经移除；不要用历史首版说明解释当前行为。

## 1. 备份什么

备份的是**可继续使用的用户工作环境**，不是 Pi Desktop 安装包，也不是业务项目的源码备份。只有手动完整备份一种模式；没有自动备份、云同步或明文导出。

以下 `A` 是实际 agent 目录（默认 `~/.pi/agent`，支持 `PI_CODING_AGENT_DIR`），`H` 是用户主目录，`P` 是通过系统对话框明确选择的项目。路径来自运行环境，不写死当前开发机器。

| 类型 | 已识别的内容 |
|---|---|
| 模型与凭据 | 完整 `A/settings.json`、`models.json`、`auth.json`、已知 provider/push 凭据文件；包括配置中的 Key、请求头及已保存 OAuth 凭据，不按当前启用的供应商过滤 |
| Skill | 全局、共享 `H/.agents/skills`、项目和声明/实际加载的资源；包含 scripts、references、assets 等完整所属内容及已知锁文件 |
| 扩展、Agent、工作流 | 全局/项目标准目录，`P/.agents/agents`、`P/.agents/workflows`，完整用户工具资源；`A/desktop-agents` 的内置 Agent 用户覆盖及 `.deleted` 删除记录 |
| Agent 设置与指令 | 全局/项目 `subagents.json`、旧 `agents/settings.json`、agent-tool-description、AGENTS/AGENTS.override/CLAUDE/SYSTEM/APPEND_SYSTEM 等已知指令 |
| 记忆 | `A/agent-memory`、旧 `H/.pi/agent-memory`、项目 `.pi/agent-memory` 和 `.pi/agent-memory-local` |
| 会话 | 全部已落盘原始 JSONL；默认会话按工作区桶作为恢复资源，也读取已声明/实际加载的额外会话根和 Agent frontmatter 的 `session_dir` |
| UI 偏好 | `shared/backup-preferences.ts` 的已知 localStorage 键：主题、语言、布局、收藏、工具预设、工作区选择等；不复制浏览器 profile |
| 外部与包资源 | 配置声明、已有加载快照、授权链接指向的真实内容；已找到的 managed npm/Git 工具源及本地修改，记录可确认的版本/commit 和来源 |

项目必须明确选择，可多选；只收集其 Pi 配置、工具目录和工具指令，不遍历旁边的业务源码。祖先资源发现限制在已识别的 Git 所属边界内；没有边界时不一直向 HOME/磁盘根扩展，而是提示明确选择拥有这些工具的祖先项目。

按**资源归属**而不是脚本后缀判断内容：工具的 `.ts`、`.py`、`.db` 等必要资产可以入包。默认排除软件本体、SDK/Electron、未修改内置实现、`node_modules` 依赖树、`.git`、缓存、运行日志、临时文件和派生索引。工具 assets/references/fixtures/examples 中必要的日志等样本按资产保留，不因文件后缀误删；`trust.json` 不继承。

“完整”表示已识别的持久资源入包，或者明确报告缺项；**不是整个电脑的镜像**。环境变量、系统密钥库、无法识别存储协议的第三方扩展数据、业务附件、未落盘会话/草稿、运行中的任务和终端不在范围内。OAuth/推送等仍可能因服务端状态而需重新登录或订阅。

## 2. 导出

1. 停止活动会话、终端和后台任务；关闭可能同时改写文件的外部 CLI。应用不会强行把变化中的文件当作一致快照。
2. 按需通过系统目录对话框选择多个项目；不选择项目也会备份全局环境、记忆和全部已落盘会话。
3. 扫描完整范围，检查资源、数量、大小、来源、缺项及依赖警告。阻断项必须先解决；警告需明确确认。
4. 输入并确认 **8–1024 字符**密码，选择一个未占用的 `.pibak` 文件名。密码丢失无法恢复。
5. 导出期间暂停桌面后台写入并冻结已知 UI 偏好写入；复查文件内容摘要、资源快照和偏好。变化会要求重新扫描，而不是静默漏项。
6. 直接把清单及内容写入同目录临时**密文**，关闭并验证后通过内核“不替换”移动发布；不先落盘明文导出包，不覆盖已有档案，也不依赖硬链接。目的地不能位于实际收集的资源内部。

显式声明或实际加载的外部工具边界可以收集，并在扫描中列出。可授权链接收集真实内容；嵌套链接越出授权边界、环、大小写别名及不支持的资源会阻断，不会悄悄跳过。

## 3. 导入与启用

1. **先选文件，再输入密码。** 选档本身不要求密码；完整 GCM 认证及清单/条目验证通过后才显示可信预览。
2. 项目、外部资源和会话工作区通过原生目录对话框映射。归档里的原绝对路径只是说明，不自动作为写入授权。会话的工作区依赖未映射时，该会话资源不能发布。
3. 每个资源选择「保留当前」或「替换归档条目」。已有资源默认保留；没有智能深度合并。保留目标独有文件及不在归档里的 UI 偏好键。
4. 凭据、模型和设置经过明确配置确认后写入有效位置。扩展、Skill、Agent、工作流、提示词、用户指令、命令型凭据等须独立勾选发布；安全策略同样明确确认，含工具预设的整组 UI 偏好也保守作为策略资源处理。
5. 未批准、未映射、依赖未齐或不能安全拆分的混合配置会暂缓，并在结果中说明**尚未恢复**。设置不能间接引用并启用未批准的扩展/包；目标独有文件可能导致可执行版本混用时，替换被阻断，可保留当前版本或映射空目录。
6. 暂缓内容仍在原加密 `.pibak` 内。以后重新选档、输入密码并恢复；不会生成长期 pending 库、第二份用户备份或长期解密密钥。
7. 成功提交后重载界面和后台。只转换已知配置路径、会话 header/结构化父子引用及工作区偏好；**不全局替换聊天正文、脚本或业务文本**。业务项目和外部文件仍须自行准备。

### 工具包和依赖

保留找到的工具源及本地修改，不把软件依赖树当作用户工具一起复制。无需额外运行时依赖、可确认离线使用的 managed 工具包，经映射和启用批准后将设置来源改为恢复后的本地路径，不再依赖原缓存位置。

其他包记录可确认的来源/版本及“需重新安装/来源未解决”状态。无法安全使用的包和引用它的混合设置暂缓；导入**不调用 npm、Git、用户安装命令，也不隐式联网重装**。配置声明使用无法只读解析的 glob、未知加载方式、未找到的包或不明第三方持久存储时，会报告警告/阻断；不能据此承诺所有第三方工具都能离线运行。

## 4. 密码、格式与版本

- 只导出 `PIDESK02` / v2：固定受限参数 scrypt（N=16384、r=8、p=1）派生 256 位 key，一条 AES-256-GCM 加密流，头作为 AAD，末尾一个认证 tag；不叠加文件级加密。
- 清单和内容一起加密，外部头不显示用户路径、供应商 Key 或会话正文。单条 SHA-256 用于内容绑定，**不证明档案作者可信**。
- v1 `PIDESK01` 仅只读导入；旧公共档案只有历史三个设置字段，不能变成完整备份。旧档本来没保存的资源不能凭空恢复；私有配置与自定义内容保守要求启用确认。
- 未知容器/格式版本拒绝。新 v2 的 SDK 版本必须与当前项目锁定 SDK 一致；不匹配拒绝恢复，先使用匹配的应用版本。不能用全局 Pi CLI 版本代替项目 SDK。
- 密码不写日志、配置或 localStorage；完成、取消、选另一档和离开页面清空输入。短期派生 key 只保留在主进程操作内存，窗口绑定，十分钟过期，完成/取消/导航/销毁清理；恢复请求不重复传密码。
- 上限：单文件 8 GiB、内容总量 16 GiB、100000 个文件条目、清单 32 MiB、条目元数据 16 KiB、相对路径长度 1024/深度 64。配置内容另有受限缓冲。这些是代码上限，**不是所有极限尺寸均已压测**。

## 5. 事务、权限及崩溃恢复

恢复使用 `A/.backup-transactions/<id>/journal.json` 协调日志，目标同卷的私有 `.pi-backup-<id>-<index>` 工作区保存新/旧文件。先持久记录意图，再移动原文件、发布新文件、记录步骤，最后持久提交；多个卷不是全局原子 rename。

文件和 UI 偏好共同参与提交。异常时逆序恢复；偏好保存原值和原先是否存在。提交持久化结果不确定时保留日志，停止后台，不能贸然回滚一半或宣称成功。启动时先处理事务，再初始化 UI 偏好和启动后台；出现外部修改、身份不一致、损坏日志或离线目标卷时保留原数据/证据并阻断，而非删除恢复依据。

Windows 使用受限固定 PowerShell 工作进程操作真实 DACL，去继承并限制当前用户/SYSTEM/Administrators；校验 owner/ACL/reparse point，发布使用 `MoveFileEx` 的不覆盖及 WRITE_THROUGH 语义。不以 chmod 冒充 Windows 隔离。覆盖的凭据文件保持私有，回滚恢复原权限；辅助进程只接收编码路径/ACL，不接收用户脚本或秘密内容，空闲退出。

这不是同 SID 恶意进程、管理员或被控制宿主的隔离边界；也不承诺 secure erase、断电硬件绝对可靠或所有网络文件系统支持。Linux/macOS 原生不覆盖移动需要可用的 Python 3/系统绑定；不支持时失败关闭，不复制半成品到最终文件名。当前真实平台验收为 Windows。

## 6. 实现与回归入口

- `shared/backup.ts`、`shared/backup-preferences.ts`：单一共享契约、偏好白名单、虚拟偏好资源。
- `lib/backup/discovery.ts`、`archive.ts`、`legacy-v1.ts`：只读发现、单流档案及旧档转换。
- `lib/backup/restore-plan.ts`、`remap.ts`、`transaction.ts`、`platform.ts`：授权映射、有效配置、冲突、事务和平台安全操作。
- `desktop/backup-resources.ts`、`backup-controller.ts`、`main.ts`、`preload.ts`：已有加载快照、窗口令牌、进度/取消、停机及启动恢复门禁。
- `components/BackupSettings.tsx`、`lib/i18n/messages/backup.ts`：单模式界面与简中/繁中/英文文案。

```sh
npm run test:backup
npm run test:isolated
npm run typecheck
npm run build
npm run test:backup:window
```

`test:isolated` 串行运行 Web、desktop、backup 三组现有测试，使用私有合成 HOME/agent/TMP，并移除凭据环境变量。Windows 的测试根位于真实用户 HOME 之外：SDK 项目信任会遍历全部祖先，仅改写 HOME 而继续使用 AppData 临时目录仍可能受到真实祖先 `.agents/skills` 影响。该入口保留 Web 原有的9文件排除和5项环境跳过，没有新增跳过来隐藏失败。

`test:backup:window` 会构建应用，再使用临时 HOME/agent/profile 和纯合成模型配置运行真实 Electron 窗口探针，不读取真实用户凭据，也不对真实用户环境执行备份/恢复。它检查页面、启动门禁和桥链路；原生对话框令牌及实际导出—恢复由控制器合成测试覆盖，不应声称已自动点击完成整个原生对话框流程。
