# Pi Desktop 手动完整备份重构架构方案

> 状态：已实施；实际范围、使用方式和验证记录见 [当前备份说明](backup-plan.md)。本方案由 `plan` 基于实施前工作树与项目 SDK 1.1.0 制定，主代理整理，并根据只读 `review` 补充事务和权限约束。用户已确认产品规则。
> 本文保留设计推导和验收目标，不把尚未运行的极限/故障测试写成通过；原旧模式、隔离恢复与遗漏描述已在 `docs/backup-plan.md`、`docs/project-guide.md` 同步替换。

## 1. 核心理念与不可变约束

**备份用户的工作环境，不备份软件本体和业务项目；恢复后能够重新使用，而不只是得到一堆解密文件。**

1. 只有一种备份方式：**手动完整备份**。取消公共、脱敏、隐私模式及分类开关；第一版不做自动备份、云同步。
2. 默认包含 Key、全部已保存认证凭据、模型、用户设置、完整 Skill、用户扩展、Agent、内置 Agent 用户编辑与删除记录、工作流、提示词、主题、用户记忆和全部已落盘会话。未保存草稿与运行任务不包含。
3. 项目由用户明确选择，可以选择多个；只收集其 Pi 配置和工具资源，不扫描或归档业务源码。
4. 排除 Pi Desktop 程序、Electron、SDK、未修改的内置资源以及缓存、日志、临时文件。工具资源内的代码和必要附件不是业务源码，不按 `.ts/.py/.db` 等后缀一刀切排除。
5. 每份 `.pibak` **整体加密一次**：单次 AES-256-GCM 加密流，无文件级加密再套整包、无密码 ZIP、无另一种用户备份格式。导出直接写密文，不先生成落盘明文备份包。
6. 导出必须设置并确认密码；导入先选文件，再输入密码。无密码、错误密码、损坏档案均不能恢复或修改现有数据。密码不持久保存，丢失无法找回。
7. 恢复展示差异，按项保留或替换，第一版不做智能合并，不删除备份之外的文件。可执行内容和安全策略另行明确确认；不静默继承项目信任或改变当前权限。
8. 导出和恢复暂停后台写入，复用现有停机机制；恢复失败回滚。内部原数据暂存不是自动备份功能，也不新增用户密码或长期加密密钥管理。

“完整”指已识别用户数据和工具资源被收集或明确报告缺项，不表示把操作系统、软件运行时、所有网络服务及聊天引用的业务文件一起打包。需要重新安装的依赖、外部凭据和未映射资源必须如实标注，不能宣称完全离线恢复。

## 3. 资源范围与发现策略

定义 `A` 为后台实际 agentDir，`H` 为运行时主目录，`P` 为用户明确选中的项目。绝不在实现中写死本机路径。

| 资源 | 已确认来源/适配器 | 策略 |
|---|---|---|
| 模型、设置、认证 | `A/settings.json`、`models.json`、`auth.json`；`lib/provider-credential-store.ts` | 全量保存，不按供应商是否出现在模型列表过滤 auth |
| 其他持久认证 | `A/web-push.json`，`lib/web-push.ts`；第三方扩展存储适配器待验证 | 按已知存储协议收集，不搜索全盘秘密；环境变量、系统凭据库依赖明确标注 |
| Skill | `A/skills`、`H/.agents/skills`、项目 `.pi/skills`、有界祖先 `.agents/skills`、已声明或加载的外部资源 | 完整所属资源，包括 scripts/references/assets；单文件 Skill 不扩大到整个父目录 |
| Skill 来源 | `lib/skill-lock.ts` 的全局锁路径与项目 `skills-lock.json` | 保存来源和摘要，锁文件不代替内容 |
| 扩展、提示词、主题 | 全局/项目标准目录、配置附加路径、加载快照和已解析包资源 | 本地及不可重取内容入包，准确记录包版本/commit、配置与本地修改 |
| Agent | `A/agents`、`P/.pi/agents`、`P/.agents/agents`；`A/desktop-agents/*.md` 和 `.deleted` 标记 | 保留作用域、覆盖优先级和内置删除记录，不复制默认内置实现 |
| Agent 设置 | `A/subagents.json`、项目 `.pi/subagents.json`、旧 `A/agents/settings.json`、agent-tool-description | 保存显式用户设置，不物化程序默认值 |
| 工作流 | `savedWorkflowRoots(cwd)`：`P/.pi/workflows`、`P/.agents/workflows` 和 `A/workflows` | 保存脚本及所属辅助资源；历史任意 scriptPath 不自动授权为扫描根 |
| 记忆 | `resolveMemoryDir`：`A/agent-memory`、旧 `H/.pi/agent-memory`、`P/.pi/agent-memory`、`P/.pi/agent-memory-local` | 完整内容，保留来源作用域与旧位置兼容 |
| 指令 | 加载器返回的 AGENTS/AGENTS.override/CLAUDE、SYSTEM/APPEND_SYSTEM 来源 | 项目及祖先仅收集明确工具指令，不扫描其旁边的业务文件 |
| 会话 | `A/sessions`；其他实际落盘会话根待验证 | 保存所有已落盘会话与结构化父子关系，不包含引用的项目文件 |
| UI 用户状态 | 已知 localStorage 持久偏好键 | schema 化导出语言、主题、布局、收藏等；排除草稿、缓存，不复制 Chromium profile |
| 权限与安全策略 | 全局 auto-mode 与项目 `.pi/automode.local.json`，trust 单独处理 | 用户策略可保存，恢复默认保留当前策略；旧 trust 不自动授予新环境权限 |

### 3.1 不执行资源的只读发现

`lib/skills-service.ts` 的 `loadSkillsWithInstallInfo(cwd)`、SDK ResourceLoader 与 DefaultPackageManager 提供路径和来源信息，但不能直接调用完整 `reload/resolve` 作为备份扫描：这些流程可能加载扩展、安装缺失包、执行配置的 npm 命令或刷新 Git 来源。

采用三路汇合：**已加载资源快照 + 标准持久资源目录 + 配置声明的只读解析**。停机前由后台给出实际已加载的资源元数据和来源，不为扫描创建会话、import 扩展、执行凭据命令或联网安装。

SDK 适配封装在版本边界内，不假定全局 Pi 与项目 SDK 版本一致。第三方动态资源没有可获取快照时，报告具体缺项，不能静默认为“已完整”。

### 3.2 外部根与资源边界

配置 URL 不是本地资源目录。外部根来自已识别资源或用户原生对话框授权；必要授权纳入扫描流程。

对授权链接目标复制真实内容，不把失效链接当成备份成功，也不在恢复时自动重建任意链接。以 realpath、文件身份、访问集合和深度/数量/字节限制防循环。只读取该工具资源的所属边界，严禁顺着扩展路径扫描整个项目、HOME 或磁盘。

已识别资源不可读、边界不明、实际内容缺失时，区分：
- **阻断项**：用户必需数据无法收集或归属不安全，不能生成自称完整的成功结果。
- **外部依赖项**：未包含的运行依赖、系统凭据、网络服务；必须展示具体恢复能力和限制并要求确认。

包安装型扩展记录实际来源、版本/commit、必要配置、本地修改和依赖闭包状态。不要复制 Pi Desktop 的 node_modules 或 vendor/npm-bundle。未保存运行依赖时标记 `requiresReinstall`，导入不自动联网、不执行安装脚本、不宣称离线可用。

| `desktop/backup-controller.ts`、`backup-platform.ts` | IPC 授权、令牌、生命周期、ACL/文件发布 |

## 5. Manifest 与单次加密容器

```ts
type Manifest = {
  formatVersion: 2;
  archiveId: string;
  appVersion: string;
  sdkVersion: string;
  createdAt: string;
  roots: RootDescriptor[];
  resources: ResourceDescriptor[];
  entries: EntryDescriptor[];
  unresolved: Diagnostic[];
};
```

资源身份由类别、作用域、逻辑根、来源身份及资源内路径组成，不能只用名称或旧绝对路径。每个条目记录 resourceId/rootId、relativePath、size、sha256；资源记录版本/来源、依赖、启用状态、用户覆盖及 `offlineReady/requiresReinstall/unresolved`。

原始路径、Key 和完整清单均在密文内；公开头仅含受限的解析和密码派生参数。敏感标记支持组合：credential、private-content、executable、security-policy。预览不回显秘密。认证成功仅说明密码和字节匹配，不意味着来自可信发布者。

```text
公开固定头：magic / version / lengths / scrypt parameters / salt / nonce
一个 AES-256-GCM 密文流：资源记录 / 文件内容 / Manifest 尾帧
一个认证 tag
```

公开头为 AAD；每次导出随机 salt/nonce。沿用现有 scrypt 基线 N=16384、r=8、p=1、32字节输出，并限制不可信档案声明的成本，参数可随格式版本演进。第一版不必增加压缩。

源读取验证身份、状态和摘要，发现导出期间变化即失败。密文写同目录临时文件，完整 flush/关闭/校验后通过平台支持的**原子不覆盖**操作发布。硬链接可作优化但不作为通用前提；不支持安全发布时失败并提示换位置，不能复制半成品到最终文件名后宣称原子。

全量 GCM 认证成功前，候选元数据不显示为可信预览、不修改有效数据。后续解包绑定同一档案内容和再次认证，阻止预览后换文件。密码仅存在操作内存中；派生密钥也仅在操作生命周期短期保留，结束、超时、取消、导航、窗口销毁释放。JS 字符串无法保证物理零化，不作此承诺。

## 6. 共享契约和界面状态机

以下是架构草案，不是已存在接口：

```ts
type Decision = {
  resourceId: string;
  conflict: "keep" | "replace";
  activation: "defer" | "enable";
};

backupSelectProjects(): Promise<ProjectSelectionResult>;
backupSelectMappingTarget({ rootId }): Promise<MappingSelectionResult>;
backupScan({ projectTokens, operationId }): Promise<ScanResult>;
backupExport({ scanToken, password, confirmPassword, operationId }): Promise<ExportResult>;
backupInspect({ kind: "select" }): Promise<SelectionResult>;
backupInspect({ kind: "unlock", fileToken, password }): Promise<InspectionResult>;
backupRestore({ inspectionToken, mappingTokens, decisions,
  configurationConsent, operationId }): Promise<RestoreResult>;
backupCancel({ operationId }): Promise<CancelResult>;
```

采用判别联合结果，共享定义避免组件重复声明。真实文件/目录由原生对话框授权，渲染层不能传任意写入路径；令牌绑定窗口、操作、期限、档案摘要和计划摘要。resourceId 标识事务级决策单元：独立配置文件及完整工具资源；同一资源的归档条目全部应用或全部回滚，不能让半个 Skill 覆盖后仍声称可用。

“替换完整资源”只替换归档中对应条目，保留目标独有文件；禁止直接交换整个目录而丢掉独有附件。预览必须列出目标独有条目及混合版本风险；不能证明叠加结果安全、可用时阻断该资源恢复，用户可保留原资源或映射到新的空目录，本流程不删除那些独有文件。该规则是文件级叠加替换，不是配置内容智能合并。

导出：**选择项目 → 扫描 → 范围/缺项预览 → 设置并确认密码 → 选择保存位置 → 导出 → 结果**。

导入：**选择文件 → 输入密码 → 全量认证 → 可信预览 → 路径映射/冲突/启用确认 → 暂存 → 提交 → 验证并重载 → 结果**。

结果区分已生效、待确认未恢复、需重新安装、需重新登录、未映射与失败。进度包含扫描、验证、写入和回滚；取消发生在提交期间时，完成安全回滚后才报告取消。

## 7. 有效恢复、启用确认与映射

普通配置、模型和凭据确认后恢复到有效位置；冲突保留或替换，不再一律放入 backup-imports。配置里的 `!command` 凭据、扩展引用、MCP 启动命令和权限设置可能在加载时执行或扩大权限，不能仅凭文件类别判定安全。

**第一版不引入长期 pending 加密资源库或额外密钥管理。** 未批准的可执行资源不发布、不写进自动发现目录，也不把其路径写进有效配置；本次操作解密暂存及时删除，完整内容仍留在原 `.pibak`。界面报告这些项“待确认、尚未恢复”，用户以后重新选择同一档案并输入密码完成受控恢复，无需手工复制文件，也不保存密码。

混合配置采用保守的原子决定：若含未批准命令或安全策略且无法可靠分离，暂缓整个配置文件，明确其模型/凭据尚未生效；第一版不为此开发复杂配置投影或隐式字段合并。只有已知 schema 下的路径映射、显式安全策略保留与启用处理可以进行确定性转换，并展示差异。

批准后才将可执行资源发布到有效位置。检查主会话、子代理、Skill 查询、Agent 重载、工作流解析和项目自动发现，防止未批准引用被重新加载；不能加载后再过滤。

用户权限策略默认保留当前值，可独立确认替换；旧 trust 不自动迁移为授权。如果配置原文含权限策略且不能安全处理，暂缓该文件，不静默更改权限。

映射以 rootId 为单位：agent 根重定位，项目与外部资源由用户指定新位置。只改已知配置字段、会话 cwd 和结构化关系，不全局替换聊天正文、脚本字符串或任意历史绝对路径。未知引用列入结果，不保证项目业务文件引用仍有效。

## 8. 恢复事务、崩溃恢复与多卷

复用 `withStoppedBackend`、`backup.status` 和现有 `backend.shutdown`；不重写退出/进程树算法。事务未解决时，禁止 finally 或启动流程重启后台。

### 8.1 正常事务

1. 停机、冻结 UI 持久设置写入，验证档案、路径授权、计划摘要、目标当前内容和空间。
2. 创建各目标卷私有事务目录及协调 journal。原文件、新文件、原权限与相关 UI 键原值都在修改前完整暂存，记录目标是否存在、文件身份、原摘要、预期新摘要及步骤。
3. 先持久化原内容、新文件及步骤意图，再在目标卷内原子发布新文件或替换；验证内容和权限，并持久化步骤完成记录。写入意图不代表替换已发生，缺少完成记录也不代表替换未发生。
4. 应用被批准配置和 UI 设置，确认所有发布与参与者记录已经持久化，再持久化全局 committed；只有其持久化成功后才清理原数据和暂存。重建派生索引并允许后台重启。
5. 出错或提交中取消，按记录逆序回滚；新建文件撤销，替换文件恢复原内容和适用原权限。只处理本事务拥有的修改。

journal 使用原子更新或带长度/校验、可检测尾部截断的追加记录，并定义序号与状态迁移；文件 flush、journal flush、必要目录元数据持久化和平台替换顺序必须形成可测试协议。持久化失败即停止后续发布，不能清理恢复依据。

目标被外部程序改动时，回滚不能强行覆盖外部修改；保留原数据和 journal，进入 recovery-required 并明确告知用户。停后台不等于停所有 CLI，导出源与恢复目标均需复核身份和摘要。

UI 持久偏好是事务参与者：journal 保存每个受管键的原值和“原先是否存在”，分别记录应用/回滚结果；任何写入异常不得吞掉，须进入失败处理。启动恢复握手先于 UI 偏好初始化与后台启动，恢复界面完成键恢复并确认后才放行。窗口销毁或多键中途崩溃时，下次启动继续回滚或已提交清理；不得只恢复文件而留下半更新 localStorage。

### 8.2 原数据保护

第一版采用经验证的私有目录与 OS 访问控制保护事务文件：Windows 显式验证当前用户 ACL、继承和 reparse point，其他平台验证等价权限；不能把 chmod(0700) 当作 Windows 隔离。

这与现有有效配置本来以明文存储一致，不给单次备份包叠加另一层加密。ACL 无法满足敏感暂存保护时，在修改前阻止恢复；不得降级到公共临时目录。删除仅代表清理，不承诺 secure erase。

保护同时覆盖最终有效文件：替换时保留经验证安全的原权限，新建凭据等敏感文件使用受限权限，不能发布后继承宽松目标目录 ACL 而暴露秘密。发布前后都验证权限；需要收紧原权限时展示变化，无法满足安全要求则失败回滚。

### 8.3 崩溃和多卷

启动先处理事务，早于后台、资源加载和 UI 持久偏好初始化：未提交回滚，已持久提交继续清理；不认识或无法验证的目录不得直接删除。新事务目录与旧 `.backup-restore-*` 清理分离。

对于“替换成功但完成记录尚未持久化”的步骤，对照意图中的原状态、预期新状态、文件身份和摘要判定实际结果；确定未应用则跳过，确定已应用则按事务状态回滚或清理，存在第三种状态或证据不足则进入 recovery-required。committed 缺失、截断或持久化失败不得按已提交处理，更不能先删除原数据。启动解析 journal 仍校验授权根、卷身份、相对路径和重解析点，不能信任其中任意路径而执行读写或删除。

多卷不是一次全局原子 rename，而是持久记录协调的可回滚事务；每卷独立暂存，记录卷身份。外部卷断开或身份变化时保留门禁，等待恢复或显式安全处置，不能启动半恢复环境。

取消、启动恢复与常规恢复必须使用同一事务引擎。Windows 文件占用、原子不覆盖发布、flush 持久性、ACL 及跨卷恢复需要实际故障注入验证。

## 9. 旧档兼容

旧公开档标明“仅有历史少量设置”，旧私有档列出实际条目与缺项，不把不存在的内容补造为完整。未知未来容器或 Manifest 版本拒绝，格式错误不触碰有效数据。

## 10. 六阶段实施顺序

1. **范围与契约**：建立资源 catalog、Manifest、结果 schema 和合成夹具；核实额外会话根、持久凭据、动态资源和 UI 键。
2. **只读发现**：加载快照与 SDK 适配，覆盖授权外部根、链接、资源身份、依赖和缺项；证明扫描不 import/spawn/install。

5. **事务与启动恢复**：私有暂存、原数据保护、无硬链接提交、多卷 journal、回滚、故障注入和停机接入。
6. **UI 与交付验收**：移除旧模式，完成密码、进度取消、冲突映射、多语言；隔离环境实测后更新旧文档。

- 空环境恢复 Key/凭据、模型、设置、完整 Skill 附件、用户扩展、内置 Agent 修改/删除标记、工作流、记忆、会话并能继续使用。

- 全局与多项目路径映射，旧记忆位置、结构化会话关系和 UI 路径偏好。
- 扩展依赖缺失按 requiresReinstall 报告，不运行安装脚本；未确认项无加载或执行副作用。

### 加密与输入安全
- 空密码、错误密码、篡改、截断、过大帧、超限 KDF、未知未来版本均失败，有效数据不变。
- key、凭据、路径与清单不出现在档案明文及日志/错误/持久状态。
- 链接循环、junction、路径穿越、ADS、大小写碰撞、父目录替换、同大小改源、预览后换档案。
- 固定信任边界内读取合法 UNC 资源；不可信归档相对路径不得注入 UNC/绝对目标。

### 事务与交互
- 原子导出且不覆盖旧档；无硬链接文件系统、磁盘满、文件占用、跨卷及卷断开。
- 在 journal、暂存、替换、commit、清理边界终止进程，重启回滚或进入恢复门禁；特别覆盖发布成功但完成记录未落盘、journal 尾部截断和 committed 持久化失败。
- 完整工具资源恢复保留目标独有附件；混合版本存在风险时阻断而非删掉附件或误报可用。
- UI 多键恢复中途崩溃、localStorage 配额/权限失败和窗口销毁，验证键的存在性及原值回滚。
- 敏感文件新建/替换后权限不放宽，宽松目标 ACL、权限设置失败和权限回滚纳入测试。
- 原目标被外部进程替换时不强行回滚覆盖；保留恢复依据。
- 取消、离开页面、窗口销毁、令牌超时清理密码；提交中取消必须安全收尾。
- 普通失败与已提交但重载失败分开报告，不能因为重载失败误报数据完全未写入。
