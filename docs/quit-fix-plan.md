# 完全退出进程残留修复

## 范围

- Windows 主窗口关闭仍隐藏到托盘；仅修复显式退出、后端 restart/备份停止时的进程生命周期。
- 不按 `Pi Desktop.exe` 名称杀进程，不触碰其他实例或用户配置，不引入 native Job Object 依赖。
- 已复现：后端调用现有 runNpx 启动本地离线任务后，原退出路径留下同名后代；结束残留任务后隔离主程序才退出。

## 设计

1. Windows 在请求清理前采集本次 backend PID 的进程树，身份包含 PID、父 PID、创建时间。清理前后都验证身份，拒绝结束复用 PID。
2. 主进程使用 `backend.shutdown({ holdForExit: true })`。后端关闭新请求/包管理任务，释放请求、PTY 和会话后应答，但保持根进程存活，避免先自退导致后代失去归属。
3. 主进程在同一退出期限内回收当前树与清理前确认的后代，然后结束后端。超时直接对仍存活的本次 backend 树兜底。未确认后端结束不得 restart。
4. 直接后端调用原 `backend.shutdown({})` 保持自退兼容；备份必须收到资源清理成功并确认后端已停止，超时/异常不得被视为安全备份。
5. PTY、会话同步异常逐项隔离，不阻止其他资源清理。主进程先建立退出兜底再销毁 UI，显式捕获异步错误，避免重复退出、未处理 rejection。
6. npx 支持请求取消，退出开始后拒绝新启动；取消不能仅终止包管理器父 PID而遗漏其任务树。

## 验证

- 单测：树归属、PID 复用保护、枚举失败、退出幂等、同步销毁异常、后端无响应、备份安全条件。
- 类型检查、桌面回归及后端 IPC 冒烟。
- Windows 隔离真实托盘点击：空闲、正在执行离线 npx 多层任务、后端不响应；本实例相关 PID 全灭且无关实例保持运行。
- 构建新的安装包与校验和，保留旧安装物；不自动结束当前使用的实例。

## 约束

纯进程树快照无法保证捕获扫描间隙内瞬间派生并脱离的任意第三方守护进程，不能宣称等价 Windows Job Object。当前方案通过保持后端根存活、清理前快照及受管入口的取消回收来修复已复现路径。进程枚举/结束失败必须记录并在测试中暴露，不能退化为按名称杀进程。
